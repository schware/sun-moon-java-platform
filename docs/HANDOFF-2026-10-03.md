### 4-1. 세 단말 화면(POS·KDS·DID)의 통신 코드

지금 `src/lib/deviceServer.ts`(주문 목록·상태 바꾸기·영업일·메뉴판·WebSocket 주소)와
`useTerminalSocket.ts` 가 세 저장소에 복사본으로 있고, 서로 조금씩 다릅니다(KDS 만 라벨·비상 모드).

| 안 | 모양 | 좋은 점 | 대가 |
|---|---|---|---|
| ① 공통 패키지 | 새 저장소 `sun-moon-terminal-common` 을 세 화면이 git 의존성으로 | 저장소 구조는 그대로 | 공통 코드를 고칠 때마다 패키지를 올리고 세 화면을 다시 빌드 |
| ② 한 저장소로 합치기 | `pos/` `kds/` `did/` + `common/` (npm workspaces) | 한 번 고치면 셋 다 — 가장 단순 | 저장소 셋을 하나로 옮기는 작업, 배포 경로(nginx 폴더)는 그대로 |
| ③ 복사본 유지 + 맞추는 검사 | 지금 그대로 두고, 같은 파일이 갈라지면 알려 주는 스크립트 | 가장 적게 바꿈 | 근본은 그대로 — 사람이 맞춤 |

**정해 주실 것:** ① / ② / ③ 중 하나. 셸(Electron)이 화면 번들을 받는 방식(§8)과도 맞물립니다.

### 4-2. 실패 재처리

Device Server 안에는 **재처리의 공통 자리가 이미 있습니다**(`ReprocessService` — 매출 분해, 라벨 PRINT 를 한
틀로, BO 재처리 화면이 이걸 부름). 공통화의 질문은 **Order·APP-SERVER 의 실패**(채널 전달 실패 등, 업무
정의서 §5.8 배치 7종)를 어디서 되돌리느냐입니다.

| 안 | 모양 |
|---|---|
| ① 서비스마다 같은 틀을 복사 | 각자 실패 표 + 재처리 주소. BO 가 셋을 부름 |
| ② Device Server 의 재처리 자리 하나로 모으기 | 다른 서비스는 실패를 거기에 적기만 — 되돌리는 주인은 하나 |
| ③ 공통 라이브러리로 틀만 나눠 쓰기 | `sun-moon-platform-core` 같은 곳에 틀, 각 서비스가 자기 실패를 들고 있음. Spring 서비스들은 지금 core 를 쓰지 않음 |

**정해 주실 것:** 실패를 **누가 들고 있고 누가 되돌리는가**. 09-18 기록대로 "상태 기계는 규칙이 달라 합치지 않는다"는
원칙과 함께 보셔야 합니다 — 틀(표·화면·재시도)은 같아도, 무엇을 다시 할지는 서비스마다 다릅니다.
