## Sun&Moon 이 정한 것

| 결정 | 내용 |
|---|---|
| 토큰은 제외 | 단말의 API 통신 토큰은 결국 **장비 토큰**이 될 수밖에 없어서 뺀다. |
| KDS·DID 의 짝 = STORE-ID | 같은 매장의 KDS 와 DID 가 함께 움직인다. 따로 묶는 설정은 없다(이미 그렇게 동작). |
| 페어링 코드 제거 | 코드 → 기기 토큰 방식을 전부 걷어낸다. **셸도 웹 단말처럼** 매장·장비를 입력한다. |
| KDS MAIN / SUB 유지 | **BO 장비 화면의 KDS 역할**로 정한다(예: `kds-01` MAIN, `kds-02` SUB). |
| 서버 확인 | 메인의 일(수령·다시 부르기·전부 조리완료·라벨 다시)을 서버가 확인한다. |
| 비상 수령 | MAIN 이 3분 넘게 끊기면 SUB 가 수령하고, 비상 수령으로 남는다. |

## 배포할 때

1. **BO 장비 화면에서 KDS 역할을 정합니다** — `kds-01` MAIN, `kds-02` SUB. 비워 두면 "모름"으로 보고
   화면이 고른 역할을 쓰며 서버도 막지 않으므로, 순서가 바뀌어도 매장은 멈추지 않습니다.
2. 배포 순서: Device Server(이때 V9) → BO → channel-order → POS·KDS·DID 화면. 한 번에 한 빌드씩.
3. 확인: KDS 메인으로 열면 메인 화면, `kds-02` 로 메인을 골라도 생산 화면으로 바뀜. 생산 KDS 에서
   다시 부르기 요청은 403. 메인을 끄고 3분 뒤 생산 화면에 비상 수령 칸.
