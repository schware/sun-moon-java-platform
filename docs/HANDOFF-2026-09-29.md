## 2. 확인한 것 (전부 시험 매장 `test-pair` 로, 끝나고 지움)

- 페어링: 발급 → 페어링 → 토큰으로 요청 → 해제 → 같은 코드 두 번은 404.
- 역할: SUB·POS 의 다시 부르기·강제 완료·수령 403, MAIN 통과. 다른 매장 주문 403.
- 셸: 공인 주소로 페어링 → 토큰 암호화 저장 → 화면이 토큰으로 `/orders` 200(자기 매장만) →
  외부 fetch 는 CSP 로 막힘. 원장은 화면이 남의 매장을 적어 보내도 기기 신원으로 적음.
- 라벨: 아메리카노 3 + 라떼 1 → 강제 완료 → 작업 4 → 셸(KDS-MAIN)이 가짜 프린터로 4장(CP949) →
  PRINTED. 재출력 MAIN 만, "재출력 1, 2".
- KIOSK: 셸이 손님처럼 눌러서 → 가상 결제 → 채번 → 주문 ACCEPTED(`tp-kiosk`/000001) →
  매출 분해까지(`tr_sale_payment` 에 SUNMOON_PAY). 1원 결제 409.
- channel-order: 앱 출처만 CORS, 다른 사이트 403, 같은 출처 POST 는 그대로.

시험하는 법과 치우는 순서(함정 포함)는 메모리에도 적어 두었습니다 — 요지는 FLOW.md 와 셸 README.
